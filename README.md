# Election Spark

Create an extremely polished, premium, Apple-inspired interactive school pre-election campaign website designed specifically for an iPad.

The website should feel like an Apple product launch mixed with a playful, high-energy interactive campaign experience. It must be visually sophisticated, extremely responsive, funny, memorable, and easy for students to understand without instructions.

IMPORTANT: Implement all of the following requirements together. Do not simplify or remove the interactive feedback.

CORE ELECTION FLOW

There are two completely separate stages:

1. Boy Vice President

2. Girl Vice President

The student completes the Boy Vice President selection first, then proceeds to Girl Vice President.

There is NO reset button. After each student finishes, the webpage will simply be reloaded. On every fresh page load, the application must automatically return to the opening screen.

Do not create a complicated voting backend. This is an interactive campaign presentation.

IMPORTANT TECHNICAL REQUIREMENT:

Do not depend on external audio files that may fail to load.

Prefer generating simple UI sound effects programmatically using the Web Audio API, such as:

- short oscillator-based buzzer

- short positive chime

- confirmation tone

The sounds must be triggered only after the user taps the screen, so they comply with iPad/mobile browser autoplay restrictions.

If audio cannot play, the visual animation must still work perfectly.

EXTREMELY IMPORTANT: VERCEL DEPLOYMENT RELIABILITY

The website MUST work reliably after deployment to Vercel.

Do not build the implementation around assets that only exist inside the development environment.

Every image, icon, logo, sound, font, or other asset must be handled in a Vercel-safe way.

IMPORTANT ASSET RULES:

1. Do not use temporary local preview URLs.

2. Do not reference files that exist only on the developer's computer.

3. Do not rely on absolute filesystem paths.

4. Do not rely on localhost URLs.

5. Do not use external image URLs if they are unnecessary.

6. Store required static assets inside the project's public/static asset directory and reference them using deployment-safe relative paths.

7. The provided Peacock logo must be included as a real project asset and referenced correctly.

8. If an asset cannot reliably be bundled, recreate the visual using CSS/SVG/code rather than depending on a fragile external URL.

9. All important UI icons should preferably be inline SVG or CSS-based.

10. The application must not break if an optional decorative asset fails.

Before considering the website complete, verify that every asset path works in a production Vercel build.

---

VERCEL / PRODUCTION REQUIREMENT

The site must behave identically in:

Development:

localhost

AND:

Production:

Vercel deployment

Do not assume that an asset available during development will automatically be available after deployment.

Avoid dynamic asset loading that could result in broken images.

The Peacock image must have a fallback so that if the primary image unexpectedly fails, the card still displays a clean Peacock symbol instead of a broken-image icon.
